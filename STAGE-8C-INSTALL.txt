99's Guide — Stage 8C Snapshot + Exact Parity
================================================

STATUS BEFORE THIS STAGE
------------------------
Stage 8A: PASS
Stage 8B: PASS

PURPOSE
-------
Copy the 19 Stage 8B private mirror tables from Supabase/PostgreSQL into D1,
without switching any production read route yet.

This keeps Supabase untouched and gives us an exact D1 snapshot before Stage 8D
write mirroring.

IMPORTANT SAFETY
----------------
- Supabase rows are SELECTed only.
- Existing shared D1 content is not changed.
- Application reads are not switched.
- server.ts is not changed.
- No BEGIN/COMMIT statements are generated.
- The exporter rejects any INSERT statement >= 95 KB to stay below D1's
  100 KB SQL statement limit.
- Keep the generated stage8c-private-snapshot.sql private. It contains a mirror
  of database rows and may include sensitive account/auth fields.

STEP 1 — EXPORT CURRENT SUPABASE SNAPSHOT
-----------------------------------------
From project root:

node export-stage8c-private-snapshot.mjs

Expected:
STAGE 8C SNAPSHOT EXPORT PASS

It creates:
- stage8c-private-snapshot.sql
- stage8c-private-snapshot-manifest.json
- stage8c-private-snapshot-report.txt

STOP if the exporter reports an oversized row/statement.

STEP 2 — IMPORT SNAPSHOT TO REMOTE D1
-------------------------------------
From project root:

cd cloudflare-content-api

npx wrangler d1 execute 99s-guide-content --remote --file=..\stage8c-private-snapshot.sql -c wrangler.jsonc

cd ..

This is the only D1 write in Stage 8C.

STEP 3 — EXPORT REMOTE D1 READ-ONLY
-----------------------------------
From project root:

export-stage8c-d1-remote.cmd

Expected:
STAGE 8C REMOTE D1 EXPORT PASS

This creates:
stage8c-d1-export.sql

STEP 4 — EXACT PARITY
---------------------
From project root:

node verify-stage8c-exact-parity.mjs

Expected:
Every table = PASS
and final line:

STAGE 8C EXACT PARITY PASS

STOP THERE.
Send ChatGPT:
1. Stage 8C snapshot exporter output

Do not begin Stage 8D until Stage 8C is marked PASS.
