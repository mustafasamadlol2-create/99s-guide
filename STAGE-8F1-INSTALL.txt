SAFETY DECISION
---------------
Authentication/session validation is NOT cut over to D1.

requireUser / requireAdmin / requireOwner and /api/auth/me continue using
Supabase for authoritative sessionVersion/account security validation.

Reason: the Stage 8D private mirror is asynchronous. A several-second stale
sessionVersion/ban/role snapshot must never become an authorization authority.

This means Stage 8F reduces normal application reads without weakening session
revocation or account-security semantics.

CUT OVER IN 8F-1
----------------
Guarded D1 primary + Supabase fallback:
- GET /api/users
- GET /api/flashcards/progress
- GET /api/progress/:userId/:materialId
- GET /api/notifications
- personal half of GET /api/calendar/events
- GET /api/qa/:lectureId

Existing shared-content D1 behavior remains unchanged.
