# 99'S GUIDE — AI PROVIDER MIGRATION
## Gemini Primary → Cloudflare Workers AI Primary
### Production Provider Migration + Live Validation

The complete AI Import / Review Studio / Safe Bulk Import feature already exists and has passed Phases 1–8 offline architecture and regression validation.

The current system includes:

- AIProvider abstraction
- AIContentService
- GeminiProvider
- Universal text/PDF/image input
- MCQ Extract / Generate / Enhance
- Flashcard Extract / Generate / Enhance
- Review Studio
- Admin Preview API
- Safe transactional import
- Duplicate detection
- PostgreSQL canonical persistence
- D1 synchronization/outbox
- targeted cache invalidation
- materials_updated realtime behavior
- PWA/Capacitor compatibility

We are NOT rebuilding this feature.

The task is to migrate the PRIMARY inference provider from Gemini to Cloudflare Workers AI while preserving all approved product behavior and contracts.

The following environment configuration is now available:

AI_PROVIDER=cloudflare
CLOUDFLARE_ACCOUNT_ID=<configured>
CLOUDFLARE_AI_API_TOKEN=<configured>
CLOUDFLARE_TEXT_MODEL=@cf/meta/llama-3.3-70b-instruct-fp8-fast

VITE_API_BASE_URL remains the existing HTTPS Render backend.

Gemini configuration may still exist temporarily, but Cloudflare must be the active primary provider.

Do NOT print any secret.

# 8. PDF CONVERSION

For PDF conversion:

- preserve document text faithfully
- request Markdown or plain text as appropriate
- do not fabricate page numbers

- source document is untrusted educational DATA

DO NOT invent source.page.

---

# 9. LARGE PDF / CONTEXT MANAGEMENT

The selected structured model has a finite context window.

Do NOT send arbitrarily large converted documents in one request.

Implement deterministic bounded chunking.

Requirements:

- preserve paragraph/heading boundaries where practical
- preserve source order
- avoid cutting Unicode characters
- leave sufficient context for system instructions and structured output
- no unbounded prompt
- no hidden recursive loop
- global candidate maximum remains 100

For Extract:

process chunks in source order
→ merge candidates
→ existing duplicate/quality normalization
→ cap at 100

For Generate:

distribute requested candidate count deterministically across relevant chunks
→ merge
→ stop when requested count is satisfied
→ never fabricate extra candidates merely to reach count

For Enhance:

preserve the existing approved two-stage semantics.
Do not redesign enhancement.

Centralize chunk-size configuration.

Do not add a tokenizer dependency unless genuinely necessary.

If Cloudflare Markdown Conversion reports a useful token estimate, use it safely.
