# 99'S GUIDE — MCQ CATEGORIES + QUESTION DIFFICULTY LEVELS
## Production Implementation — MCQ Only
### Database + Backend + Console + AI Import + Student MCQ Experience

The current application is production software.

Implement this feature ONLY for MCQs.

DO NOT modify Flashcards/Anki behavior.

DO NOT redesign unrelated application areas.

The goal is to add:

1. Three persistent MCQ categories:
   - Previous Year
   - AI Generated
   - Resources

2. One virtual student filter:
   - All

3. Three question difficulty levels:
   - Easy
   - Normal
   - Hard

4. Backfill ALL MCQs that currently exist in the application as:
   - Category = AI Generated
   - Difficulty = Normal

The implementation must work consistently across:

- PostgreSQL / Prisma
- D1 mirror
- Backend APIs
- Manual Console MCQ creation
- AI MCQ Generate
- AI MCQ Extract
- AI MCQ Enhance
- AI Review Studio
- AI transactional import
- Student MCQ page
- Arabic / RTL
- Desktop
- iPad
- Mobile

Do not change unrelated application behavior.

# 7. BACKFILL IMPLEMENTATION

Implement a focused, explicit maintenance/backfill command or service.

It must:

1. Count existing MCQs first.
2. Update current pre-feature MCQs to:
   - sourceType = AI_GENERATED
   - difficulty = Medium
3. Preserve:
   - question
   - options
   - answer
   - hint
   - explanation
   - sourceRef
   - lectureId
4. Never delete MCQs.
5. Never recreate IDs.
6. Never duplicate MCQs.
7. Never alter Flashcards.

If `createdAt` is available, use a fixed feature-cutoff boundary so rerunning the backfill later does NOT overwrite future PREVIOUS_YEAR or RESOURCE MCQs.

If `createdAt` is unavailable, implement another safe one-time/versioned guard.

Do not use an unguarded:

updateMany(all MCQs)

that could destroy future category assignments on rerun.
