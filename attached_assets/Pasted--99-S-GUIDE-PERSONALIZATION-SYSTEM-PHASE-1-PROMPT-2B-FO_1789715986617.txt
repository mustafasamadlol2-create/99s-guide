# 1. CRITICAL CORRECTION — SUBJECT ORDER

The current report states:

- subject-order deduplication and completion
- partial subject-order normalization

That is NOT the required behavior.

The required V1 behavior is strict and deterministic:

A valid personalized subject order must:

- contain every canonical subject ID
- contain each canonical subject ID exactly once
- contain no duplicates
- contain no unknown IDs
- contain no missing IDs

ONLY a complete valid permutation is accepted.

If `home.subjectOrder` is:

- missing
- partial
- duplicated
- contains an unknown ID
- contains a missing canonical ID
- contains an extra ID
- wrong type

then the normalized result must use the COMPLETE canonical production subject order.

Do NOT deduplicate-and-complete a partial user order.

Do NOT attempt best-effort repair.

Rationale:

Customization must be deterministic and must never invent an ordering the user did not explicitly save.
