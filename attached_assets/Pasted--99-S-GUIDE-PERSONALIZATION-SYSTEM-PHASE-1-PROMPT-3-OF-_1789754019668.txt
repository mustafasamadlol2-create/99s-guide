# 13. CACHE ENVELOPE

Do not store raw unversioned objects with no metadata.

Create a small local cache envelope.

Recommended concept:

type PersonalizationCacheEnvelope = {
  cacheVersion: 1;
  savedAt: string;
  config: PersonalizationConfigV1;
};

Do NOT duplicate the user ID inside the JSON payload unless there is a strong reason.

The account identity is already represented by the cache key.

Do not include personal data.

---

# 14. CACHE VERSION VS CONFIG VERSION

Keep these concepts separate:

config.version
→ Personalization schema version

cacheVersion
→ Local storage envelope format version

Both may currently be:

1

but they are semantically different.

Do not confuse them.

---

# 15. SAVED AT

`savedAt` should be an ISO 8601 UTC timestamp.

Purpose:

- debugging
- later reconciliation
- future last-write-wins support

It is not academic data.

Do NOT use it as an authorization mechanism.

---

# 16. CACHE SIZE

Before writing local cache:

validate the CONFIG using the approved payload-size helper.

The canonical account personalization max remains:

16384 UTF-8 bytes.

Cache envelope metadata may add a small overhead.

Do not reject a valid config merely because the envelope itself adds a few bytes.

The 16 KiB limit applies to the serialized personalization config, matching the future network/KV payload contract.

---

# 17. SAFE READ

Reading cached personalization must never crash application startup.

For:

- missing key
- invalid JSON
- wrong cacheVersion
- malformed envelope
- missing config
- invalid config
- unsupported config version
- oversized config
- storage exception

return a safe result.

Recommended API:

type PersonalizationCacheReadResult =
  | {
      status: "found";
      config: PersonalizationConfigV1;
      savedAt: string;
    }
  | {
      status: "missing";
      config: PersonalizationConfigV1;
    }
  | {
      status: "invalid";
      config: PersonalizationConfigV1;
      reason: ...;
    };

Or another small explicit result type.

For missing/invalid:

config must be Classic 99 defaults.

Do not throw into React.

# 34. RESET SEMANTICS

---

# 35. APPLY SEMANTICS

Apply means:

1. Strictly validate draft.
2. committed = independent clean copy of draft.
3. draft = independent clean copy of committed.
4. isDirty = false.
5. return committed config for the caller to persist.

State-level Apply does NOT itself call KV.

It may optionally call the local storage helper only if architecture remains clean.

Preferred separation:

state reducer
≠
storage side effect

Keep pure state logic pure.
