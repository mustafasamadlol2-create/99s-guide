# 99'S GUIDE — PERSONALIZATION SYSTEM
# PHASE 4 / PROMPT 16B
## HERO + GLASS — iOS 16.0/16.1 CSS COMPATIBILITY REPAIR
### color-mix() MUST BECOME PROGRESSIVE ENHANCEMENT
### PRESERVE PROMPT 16 ARCHITECTURE AND VISUALS
### DO NOT BEGIN PROMPT 17

Prompt 16 implementation is functionally approved pending ONE compatibility issue.

The project minimum target is:

iOS 16+

Prompt 16 reports that Clear/Frosted Glass surface derivation uses:

color-mix()

However:

- Safari/iOS Safari 16.0 and 16.1 do NOT support CSS color-mix().
- Safari/iOS Safari support begins at 16.2.
- Therefore an unconditional color-mix() declaration cannot be the only valid declaration for any required Prompt 16 Glass surface/border property.

Prompt 16B exists ONLY to make the existing Glass implementation safe for the entire iOS 16+ target.

Do NOT redesign Hero.
Do NOT redesign Glass.
Do NOT begin Motion Style.
Do NOT begin Reading Size.
Do NOT alter the approved personalization state architecture.

---

# 1. PRIMARY REPAIR GOAL

Ensure every Prompt 16 use of:

color-mix(...)

has a valid non-color-mix fallback for Safari/iOS Safari 16.0–16.1.

Modern browsers supporting color-mix() should retain the approved Prompt 16 appearance.

Older supported browsers should retain:

- valid themed Glass surfaces
- valid themed Glass borders
- Clear/Balanced/Frosted distinction through supported blur/saturation behavior
- readable content
- reduced-transparency behavior
- fixed-semantic safety

No declaration required for usable Glass presentation may disappear merely because color-mix() is unsupported.

# 3. DO NOT REMOVE MODERN color-mix() ENHANCEMENT UNNECESSARILY

The approved Clear/Frosted presentation may keep its current color-mix() behavior on supported browsers.

Preferred architecture:

1. safe baseline declaration
2. optional color-mix() enhancement

For example conceptually:

```css
.some-glass-surface {
  background: var(--semantic-glass-surface);
  border-color: var(--semantic-glass-border);
}

@supports (color: color-mix(in srgb, black, white)) {
  .some-glass-surface {
    background: color-mix(...);
    border-color: color-mix(...);
  }
}

Exact selectors/variables must follow the actual implementation.

4. FALLBACK MUST BE THEME-AWARE

The fallback must use existing semantic Theme Pack values.

Preferred fallback sources:

var(--semantic-glass-surface)
var(--semantic-glass-border)

Do NOT hardcode:

Classic-specific white
Ocean-specific teal
Rose-specific pink
etc.

No per-theme Glass fallback blocks.

5. NO THEME × GLASS COMBINATORIAL CSS

Still forbidden:

[data-app-theme="rose"][data-app-glass-style="frosted"]

Compatibility must not introduce combinatorial styling.

Theme and Glass remain independent axes.

6. CLEAR FALLBACK

On Safari/iOS Safari 16.0–16.1:

Clear must remain recognizably Clear through supported properties such as the already-approved:

lower blur
lower saturation/frosting
existing transparent semantic Glass surface
existing semantic Glass border

It is acceptable if the modern color-mix surface-density nuance is unavailable on 16.0/16.1.

It is NOT acceptable for:

background to become invalid/absent unintentionally

content readability to break

The surface itself must remain valid.

10. PREFER @supports FOR EXPLICIT SAFETY

Preferred:
explicit @supports.

11. DO NOT USE @supports TO HIDE CORE GLASS RULES

The base Glass rules must exist OUTSIDE the support query.

12. CSS CUSTOM PROPERTY CAUTION

then simply placing a fallback background elsewhere may not be sufficient for every consumer.

Audit actual variable resolution carefully.

Ensure unsupported color-mix cannot make a required custom-property-derived declaration invalid without fallback.
