---

# 12. MOTION STYLE — SUBTLE

Subtle means:

less prominent NONESSENTIAL motion

without making the interface static.

Safe techniques MAY include:

- lower decorative moving-layer opacity
- reduced decorative movement prominence
- slower/calmer ambient decorative loops where safe
- reduced scale/translation flourish where existing CSS permits safe variable control
- shorter/smaller optional hover flourish

Do NOT globally slow all interaction.

Do NOT make navigation sluggish.

Do NOT modify gesture thresholds.

---

# 13. SUBTLE IS NOT "SLOW MODE"

Important:

Do not blindly multiply all durations by 2.

That can make the app feel slower rather than calmer.

Subtle should reduce perceived motion intensity, not degrade responsiveness.

---

# 14. MOTION STYLE — REDUCED

Reduced should minimize nonessential visible motion.

Safe behavior may include:

- suppress decorative looping movement
- pause/remove CSS decorative animation
- strongly reduce decorative transition transforms
- hide moving decorative particles if necessary
- preserve static presentation

It MUST preserve:

- navigation functionality
- swipe functionality
- state changes
- loading meaning
- progress meaning
- accessibility feedback
- necessary content transitions

---

# 15. REDUCED DOES NOT MEAN NO FEEDBACK

Do not remove:

- correct/incorrect indicators
- selection state
- loading state
- focus state
- route state
- current tab indicator

Only minimize unnecessary motion.

---

# 16. OS REDUCED MOTION HAS HIGHEST PRIORITY

CRITICAL.

Existing:

@media (prefers-reduced-motion: reduce)

must ALWAYS override user Motion Style.

Examples:

User selected:
Full

OS says:
Reduce Motion

Result:
OS reduced-motion accessibility behavior wins.

User selected:
Subtle

OS says:
Reduce Motion

Result:
OS reduced-motion accessibility behavior wins.

No My 99 option may re-enable animations disabled by OS accessibility.
