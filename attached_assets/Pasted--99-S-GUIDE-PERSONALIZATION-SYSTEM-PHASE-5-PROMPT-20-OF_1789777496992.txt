1. PRIMARY GOAL

Design the exact production architecture for synchronizing the existing six-axis PersonalizationConfigV1 across a user's devices.

The architecture must preserve:

current local-first behavior
current My 99 Draft/Apply workflow
account isolation
no personalization dependency for app startup
offline usability
no SQL preference storage
no client-controlled arbitrary user IDs

existing local cache as first-line persistence

The output of Prompt 20 must be an implementation-ready contract for Prompt 21.

2. ARCHITECTURE DECISION

Use this target architecture unless the current repository audit proves a concrete blocker:

Client
  ↓ authenticated existing API
Render / Express
  ↓ authenticated server-to-server personalization sync
Cloudflare Worker / KV
  ↓
Workers KV

The client must NOT call KV directly.

The client must NOT supply an arbitrary target user ID.

The authenticated backend must derive the user identity from the existing verified session/auth context.

3. LOCAL CACHE REMAINS PRIMARY FOR STARTUP

Cloud sync must NOT become required to render the application.

Never block app startup waiting for KV.

4. NO CLOUD-ONLY PERSONALIZATION

16. LOCAL SUCCESS MUST NOT DEPEND ON CLOUD AVAILABILITY

Cloud outage must not prevent the user from personalizing the current device.

Required principle:

If local persistence succeeds but remote sync cannot be reached:

local Apply should remain successful
committed config should remain applied locally
user should not lose customization
remote state should remain eligible for later reconciliation

Do NOT rollback a successful local Apply solely because KV is offline.

B. CLOUD SYNC SUCCESS

46. MULTI-DEVICE OFFLINE CONFLICT

Scenario:

Cloud revision 5.

Device B goes offline.

A applies config X.
B applies config Y.

Prompt 20 must define the supported semantics honestly.

Possible acceptable V1 interpretation:

"Last successfully synchronized explicit Apply wins in cloud."

A device with unsynced local intent may later overwrite cloud when its pending Apply sync succeeds.

If this is the chosen V1 rule:

Do not claim impossible total ordering of offline events.

47. CONFLICT CLAIM ACCURACY
