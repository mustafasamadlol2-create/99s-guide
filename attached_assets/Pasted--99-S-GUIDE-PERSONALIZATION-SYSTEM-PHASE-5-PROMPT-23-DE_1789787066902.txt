3. DEVICE VS ACCOUNT SEMANTICS

Audit and confirm the correct model.

The OS app icon belongs to the installed application on a DEVICE.

Therefore App Icon should conceptually be:

installation/device scoped

not:

account scoped

Expected behavior:

User selects alternate icon on Device A.
Device A changes icon.
Device B does not change.
Logging into another account on Device A does not automatically change the OS icon.
Logging out does not reset the icon.
Cloud synchronization never transports icon state.

Prompt 23 must confirm or challenge this based on actual platform behavior.

4. OS AS SOURCE OF TRUTH

On iOS/iPadOS, prefer the operating system as the source of truth for current icon state.

Architecture should investigate using:

UIApplication.shared.supportsAlternateIcons
UIApplication.shared.alternateIconName
UIApplication.shared.setAlternateIconName(...)

Conceptually:

supportsAlternateIcons
→ can this installation switch icons?

alternateIconName
→ which alternate icon is currently active?
→ nil means primary icon

setAlternateIconName
→ request icon change

Determine whether a separate persistent JavaScript/localStorage key is needed at all.

Strong preference:

DO NOT create redundant app-icon persistence if native OS state can be queried reliably.
