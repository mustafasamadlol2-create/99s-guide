The following is now fixed.

## Canonical relational layer

**Supabase PostgreSQL + Prisma remains the canonical relational source of truth.**

Cloudflare may include:

* D1
* KV
* R2
* Workers
* Durable Objects
* Analytics Engine
* Queues
* Cache APIs
* Workers AI

Cloudflare must:

* reduce repeated Supabase/PostgreSQL reads;
* reduce unnecessary high-frequency writes;
* provide fast read projections;
* handle active realtime coordination;
* provide aggregate telemetry;
* cache derived results;
* store binary objects where appropriate.

Cloudflare must NOT:

* create an unrelated second identity universe;
* become the source of user permissions;
* independently award points;
* independently decide Mastery;
* independently modify academic content authority;
* override PostgreSQL canonical records.

Every Cloudflare projection must reference canonical PostgreSQL IDs.

# 2. IMPORTANT INTERPRETATION

The architecture is NOT:

```text
everything only in Supabase
```

and is NOT:

```text
everything only in Cloudflare
```

It is:

```text
Durable relational truth
        ↓
Supabase PostgreSQL / Prisma
        ↓
projection / synchronization
        ↓
Cloudflare runtime services
        ↓
normal high-frequency application usage
```

The objective is to make normal usage hit Cloudflare whenever safe and appropriate while preserving PostgreSQL as the recovery/reconciliation/canonical layer.
