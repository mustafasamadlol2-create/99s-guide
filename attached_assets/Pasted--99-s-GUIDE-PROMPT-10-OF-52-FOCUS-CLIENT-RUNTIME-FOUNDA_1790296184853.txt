---

# 1. PRIMARY OBJECTIVE

Build a reusable client-side Focus runtime capable of:

```text
app opens/reloads
→ fetch canonical current Focus Session
→ establish server/client clock relationship
→ derive display countdown locally
→ survive ordinary browser/native timer suspension
→ reconcile from server after foreground/reconnect
```

And support safe client calls for:

```text
start
pause
resume
complete
abandon
```

without making the client authoritative.

---

# 2. FROZEN AUTHORITY RULE

The client is NEVER authoritative for:

* session status;
* active study duration;
* pause duration;
* completion eligibility;
* completed-session count;
* Study Events;
* Daily Metrics;
* Points.

Canonical authority remains:

```text
PostgreSQL + Focus backend
```

Client runtime provides:

```text
display state
interaction state
request retry/idempotency
recovery/reconciliation
```

only.

---

# 3. NO CLIENT COUNTDOWN PERSISTENCE

Do NOT write a countdown value such as:

```text
remaining = 2634
remaining = 2633
remaining = 2632
```

to:

* PostgreSQL;
* D1;
* localStorage every second;
* IndexedDB every second;
* React persisted state every second.

There must be:

```text
PER-SECOND SERVER WRITES = 0
PER-SECOND D1 WRITES = 0
PER-SECOND PERSISTENT LOCAL WRITES = 0
```

A local render tick is allowed.

---

# 4. CLIENT DISPLAY TIMER MODEL

The backend already returns canonical timer information including:

```text

status
startedAt
plannedEndAt

```

The client must anchor its local display to a server snapshot.

Do not simply calculate using:

```text

```

as if the user's device clock is trusted.

---

# 5. SERVER CLOCK BASELINE

At successful synchronization store an in-memory baseline conceptually equivalent to:

```text
serverNowAtSync
clientMonotonicAtSync
canonicalSnapshot
```

Then estimate display time using a monotonic client clock where available:

```text
estimatedServerNow
=
serverNowAtSync
+
(clientMonotonicNow - clientMonotonicAtSync)
```

Use:

```text
performance.now()
```

or the existing appropriate monotonic abstraction.

Do not use the client's wall-clock timezone/time setting as authority.

---

Do not scatter direct `Date.now()` or `performance.now()` calls throughout Focus code.

# 11. CANONICAL RECOVERY ON RELOAD

Reload recovery must NOT depend on retaining an in-memory countdown.

Scenario:

1. Start Focus.
2. Reload application.
3. All JavaScript memory disappears.
4. Focus runtime starts again.
5. Request `/current`.
6. Timer reconstructs correctly.

Add a deterministic test.


Do NOT persist:

* fake activeSeconds increments;
* locally invented completion;
* Points;
* Study Events;
* timer ticks.

Every cached session must be explicitly marked:

```text
NON_AUTHORITATIVE
```

in runtime semantics.

# 13. CACHE STORAGE FREQUENCY

# 22. NETWORK REQUEST BUDGET

There must be no polling every second.

Default Focus runtime must NOT do:

```text

```

Normal network calls occur on meaningful lifecycle events:

* initialization;
* mutation;
* foreground;
* reconnect;
* explicit refresh;
* carefully justified periodic safety reconciliation only if truly required.

Prefer no periodic polling in Prompt 10.

# 23. LOCAL RENDER TICK

A local display tick may occur approximately once per second when:

```text

```

Its only job is to trigger display recomputation.

It performs:

```text
network writes = 0
network reads = 0
persistent storage writes = 0
```

When `PAUSED`, a continuous second-level tick is unnecessary unless future UI specifically needs it.

# 35. CRITICAL — RETRY MUST REUSE KEY
