# 99’s GUIDE — PROMPT 11 OF 52

## FOCUS RESOURCE HANDOFF + INTERRUPTION TRACKING

## EXTERNAL PDF / VIDEO STUDY WITHOUT FALSE DISTRACTION SIGNALS

### SERVER-AUTHORITATIVE — NO QUICK NOTES — NO FOCUS UI YET

Prompts 1–10 and Prompt 9R have been completed and approved.

Prompt 11 implements the next frozen Focus capability:

```text
intentional study-resource handoff
+
return/reconciliation
+
bounded interruption observation
```

The core rule is:

# INTENTIONAL STUDY RESOURCE HANDOFF IS NOT A DISTRACTION.

Examples:

* opening a lecture PDF in the native/system viewer;
* opening a lecture video externally;
* temporarily leaving 99’s Guide specifically to consume an approved Lecture resource.

This must not automatically create an interruption.

At the same time:

# GENERIC APP BACKGROUNDING IS ONLY A POTENTIAL INTERRUPTION SIGNAL.

It is NOT:

* automatic misconduct;
* automatic loss of Points;
* automatic abandonment;
* proof the student was distracted.

Prompt 11 must preserve that distinction everywhere.

---

# 1. FIXED RESOURCE-HANDOFF MODEL

The Focus state machine already contains:

```text
ACTIVE
→ RESOURCE_HANDOFF
→ ACTIVE
```

and:

```text
RESOURCE_HANDOFF
→ PAUSED
RESOURCE_HANDOFF
→ ABANDONED
RESOURCE_HANDOFF
→ RECONCILIATION_REQUIRED
```

Prompt 11 will implement the normal runtime handoff path.

For this phase, initiating a new handoff is allowed from:

```text
ACTIVE
```

only.

Do NOT expose:

```text
PAUSED → RESOURCE_HANDOFF
```

yet, even though the frozen state graph allows it conceptually.

Reason:

the current canonical schema does not persist handoff-origin semantics, and normal product behavior does not require opening a study resource from a paused Focus state.

Do not change the frozen transition map.

---

# 2. HANDOFF PURPOSE

The student may be running a Focus Session and choose a resource belonging to that Lecture.

Example:

```text
Focus Lecture A
→ open Lecture A PDF externally
→ canonical Session becomes RESOURCE_HANDOFF
→ PDF opens using existing external/system viewer
→ student returns to 99’s Guide
→ handoff is reconciled
→ canonical Session returns ACTIVE
```

No personal Schedule event is involved.

# 3. CRITICAL EXTERNAL-RESOURCE ANALYTICS RULE

Never claim:


Name variables and analytics accordingly.

# 4. FOCUS TIME DURING RESOURCE HANDOFF

An intentional Resource Handoff is part of the Focus Session.

Therefore:

```text
RESOURCE_HANDOFF time
```

may continue contributing toward the Session's planned Focus duration.

This allows a student to spend a 45-minute Focus round studying a PDF in the native viewer without the Focus timer effectively stopping.

However:

* handoff time is Focus-session time;
* it is NOT exact resource-view time;
* it must be capped by the remaining planned Focus duration;
* it must never exceed the Session target;
* it creates no per-resource completion claim.

# 19. SERVER HANDOFF START TRANSITION

Allowed:

```text
ACTIVE → RESOURCE_HANDOFF
```

The server must:

1. acquire the same per-user advisory lock used by Focus lifecycle;
2. validate ownership/state/resource;
3. derive current active elapsed segment;
4. checkpoint accumulated active Focus time;
5. set `lastCheckpointAt = serverNow`;
6. keep the planned target stable;
7. change status to `RESOURCE_HANDOFF`;
8. emit `focus_resource_handoff_started`;
9. enqueue `FocusSession` projection.

All in one PostgreSQL transaction.
