# 9. WEBSOCKET SUBPROTOCOL AUTH

For browser/PWA connections use:

```text
Sec-WebSocket-Protocol
```

with two offered protocols conceptually:

```text
gf-v1
gf-auth.<capabilityToken>
```

The Worker:

1. parses the offered protocol list;
2. requires exactly one `gf-v1`;
3. extracts exactly one `gf-auth.<token>`;
4. validates the capability;
5. strips the credential protocol from downstream semantics;
6. upgrades using only:

```text
Sec-WebSocket-Protocol: gf-v1
```

as the selected/echoed protocol.

Do NOT echo:

```text
gf-auth.<token>
```

back to the browser.

# 65. LATE ALARM CATCH-UP — IMPORTANT

A DO alarm may execute significantly after the expected deadline.

The synchronized room must not permanently drift by making each next phase start from the late callback time.

Implement deterministic catch-up using scheduled boundaries.

Example:

```text

```

The next phase's logical start is based on:

```text

```

not blindly:

```text

```

Advance through as many already-expired phases as necessary until reaching:

* the currently active phase with a future deadline; or
* COMPLETED.

Bound the loop by `roundCount`.
