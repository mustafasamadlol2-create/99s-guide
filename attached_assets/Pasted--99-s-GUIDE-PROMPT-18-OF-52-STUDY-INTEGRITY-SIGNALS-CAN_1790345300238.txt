Prompts 1–17 have been completed.


# 1. PRIMARY OBJECTIVE

Implement a canonical PostgreSQL-backed Study Integrity signal system that can:

1. persist review-worthy deterministic observations;
2. deduplicate repeated occurrences;
3. keep exact occurrence counts and first/last timestamps;
4. preserve rule/evidence/source metadata;
5. provide private owner/admin review APIs;
6. record immutable review actions;
7. support safe triage states;
8. expose internal user/action integrity context for future Points logic;
9. never automatically punish the student.

# 8. SIGNAL STATUS

Use a small review workflow:

```text
OPEN
ACKNOWLEDGED
RESOLVED
DISMISSED
```

Semantics:

### OPEN

Unreviewed active signal.

### ACKNOWLEDGED

Reviewer has seen it but has not made a final disposition.

### RESOLVED

Reviewer confirms the technical issue was meaningful and review is complete.

This still does NOT imply punishment.

### DISMISSED

Reviewer determines no further integrity follow-up is required.

# 23. DEDUPLICATION SEMANTICS

Repeated occurrences of the same signal fingerprint should normally update one signal row instead of creating unlimited duplicates.

First occurrence:

```text
occurrenceCount = 1
firstOccurredAt = occurredAt
lastOccurredAt = occurredAt
lastReceivedAt = receivedAt
status = OPEN
```

Repeated matching occurrence:

```text
occurrenceCount += 1
lastOccurredAt = max(previous, occurredAt)
lastReceivedAt = max(previous, receivedAt)
```
