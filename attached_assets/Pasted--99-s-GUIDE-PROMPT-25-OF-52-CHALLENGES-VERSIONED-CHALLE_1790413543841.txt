### NO BONUS POINTS — NO LEADERBOARD — NO UI

Prompts 1–24 have been completed.

Prompt 25 now implements Challenges on top of the versioned Gamification system.

Frozen roadmap:

```text
Prompt 25 — Challenges
Prompt 26 — Leaderboard seasons / snapshots
Prompt 27 — Leaderboard D1 / cache
```

---

# 1. PRIMARY OBJECTIVE

Implement:

1. versioned Challenge definitions;
2. canonical Challenge instances;
3. deterministic enrollment;
4. private per-user Challenge progress;
5. deterministic completion;
6. bounded time windows;
7. automatic and manual enrollment policies;
8. progress reconciliation/repair;
9. authenticated own-Challenge APIs;
10. server-side Challenge lifecycle.

No Challenge Points rewards.

No Leaderboard.

No visible UI.

---

# 2. CORE PRINCIPLE

Challenge progress must be derived from:

```text
canonical source data
→ Prompt 22 metric provider
→ immutable Challenge definition
→ deterministic target evaluation
→ canonical Challenge progress/completion
```

Never:

```text
client says progress = 80%
→ accept
```

* Study Points authority;

* Mastery authority;

* integrity evidence.

# 39. BASELINE MODEL

Challenge progress must measure activity within Challenge window.

Do NOT simply use lifetime metric value against target.

For cumulative lifetime metrics, persist:

```text
baselineValue
```

at Challenge window start/enrollment.

Then:

```text
progress = currentMetricValue - baselineValue
```

with bounds.

---

# 40. BASELINE AUTHORITY

Baseline comes from canonical metric provider.

Client never submits baseline.

---

# 41. AUTO-ENROLLMENT LATE IN WINDOW

For weekly cumulative metrics, compute metric value at:

```text

```

If current metric provider cannot reconstruct historical value at `startsAt`, do not fake it.
