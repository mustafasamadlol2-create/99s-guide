# 99’s GUIDE — PROMPT 26 OF 52

## LEADERBOARD SEASONS + CANONICAL SNAPSHOTS

## DETERMINISTIC RANK SEMANTICS + PRIVACY-SAFE COMPETITION

### POSTGRESQL CANONICAL — NO D1 CACHE YET — NO UI

Prompts 1–25 have been completed.

Prompt 26 now implements the canonical Leaderboard domain.

Frozen roadmap:

```text
Prompt 26 — Leaderboard seasons / snapshots
Prompt 27 — Leaderboard D1 / cache
Prompt 28 — Recall canonical state / attempt
```

Do NOT implement Prompt 27 or later features early.

---

# 1. PRIMARY OBJECTIVE

Implement:

1. canonical Leaderboard season definitions;
2. weekly, monthly, semester, and all-time scopes;
3. deterministic score calculation;
4. canonical PostgreSQL Leaderboard snapshots;
5. deterministic ranking and tie semantics;
6. privacy-safe leaderboard rows;
7. safe public/private exposure;
8. rebuildable snapshots;
9. historical snapshot preservation;
10. reconciliation and repair;
11. cursor-based leaderboard read APIs;
12. own-rank lookup.

No D1 leaderboard cache yet.

No visible Leaderboard UI yet.

---

# 2. CORE PRINCIPLE

Leaderboard is:

```text
canonical Study Points
→ deterministic season window
→ deterministic score
→ canonical snapshot
→ privacy-safe rank DTO
```

It is NOT:

```text
AI ranking
intelligence ranking
academic ranking
medical competence ranking
popularity ranking
```

---

# 3. LEADERBOARD MEASURES ENGAGEMENT ONLY

Leaderboard represents Gamification activity / Study Points.

Never describe rank as:

```text
smartest
best student
strongest academically
highest mastery
most intelligent
```

Use neutral wording such as:

```text
Study Points rank
weekly activity rank
Gamification rank
```

# 47. RANK CALCULATION
