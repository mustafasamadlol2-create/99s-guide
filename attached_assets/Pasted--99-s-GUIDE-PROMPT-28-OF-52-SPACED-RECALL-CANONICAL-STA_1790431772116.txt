## SPACED RECALL CANONICAL STATE

## RECALL ATTEMPT LIFECYCLE + SERVER-DERIVED OUTCOMES + EVIDENCE CONTRACTS

### NO CANDIDATE RANKING YET — NO COOLDOWN/ANTI-FARMING YET — NO POINTS — NO UI

Prompts 1–27 have been completed.

Prompt 28 begins the Spaced Recall subsystem.

Frozen roadmap:

```text
Prompt 28 — Recall canonical state / attempt
Prompt 29 — Recall eligibility / candidate
Prompt 30 — Recall cooldown / anti-farming
Prompt 31 — Mastery initial deterministic
Prompt 32 — Retention decay / review
Prompt 33 — Mastery D1 / dashboard API
```

Prompt 28 must build only the canonical Recall attempt/state foundation.

Do NOT implement Prompt 29 or Prompt 30 early.

---

# 1. PRIMARY OBJECTIVE

Implement a canonical PostgreSQL Spaced Recall foundation that can safely represent:

```text
Recall item presented
→ user answers OR skips
→ server determines the valid outcome/evidence
→ immutable attempt history
→ rebuildable per-item Recall state
```

It must support future Recall selection, retention, Mastery, and anti-farming without implementing those later systems yet.

---

# 2. PRODUCT BEHAVIOR TO PRESERVE

Spaced Recall is a lightweight periodic recall card that will eventually present:

```text
one MCQ
or
one Flashcard
```

from previously studied material.

Future Prompt 29 will decide which item should appear.

Prompt 28 only establishes what happens once a canonical Recall item has been issued.
