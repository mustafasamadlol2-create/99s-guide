# 2. CORE PRINCIPLE

The safe workflow becomes:

```text
student requests Recall
→ server checks launch eligibility
→ server applies cooldown/caps
→ Prompt 29 selects allowed candidate
→ Prompt 28 issues canonical RecallAttempt
→ server returns short-lived interaction token
→ user answers/skips
→ server validates token/window
→ Prompt 28 determines canonical outcome
→ only legitimate objective eligible outcome may award tiny Points
```

Never:

```text
client picks question
client decides eligibility
client decides correctness
client decides reward
```
