# 99’s GUIDE — PROMPT 9R

## FROZEN FOCUS STATE-MACHINE CORRECTION

### DISALLOW `PAUSED → COMPLETED`

### NARROW CORRECTION ONLY — DO NOT START PROMPT 10

Prompt 9 implementation is accepted except for one architecture violation.

The Prompt 9 report states that completion eligibility currently allows:

```text
ACTIVE
or
PAUSED
```

when the planned active duration is reached.

This conflicts with the frozen Focus state machine.

The canonical allowed transitions are:

```text
CREATED → ACTIVE
CREATED → ABANDONED

ACTIVE → PAUSED
ACTIVE → RESOURCE_HANDOFF
ACTIVE → COMPLETED
ACTIVE → ABANDONED
ACTIVE → EXPIRED
ACTIVE → RECONCILIATION_REQUIRED

PAUSED → ACTIVE
PAUSED → RESOURCE_HANDOFF
PAUSED → ABANDONED
PAUSED → EXPIRED
PAUSED → RECONCILIATION_REQUIRED

RESOURCE_HANDOFF → ACTIVE
RESOURCE_HANDOFF → PAUSED
RESOURCE_HANDOFF → ABANDONED
RESOURCE_HANDOFF → RECONCILIATION_REQUIRED

RECONCILIATION_REQUIRED → COMPLETED
RECONCILIATION_REQUIRED → ABANDONED
RECONCILIATION_REQUIRED → EXPIRED
```

There is deliberately NO:

```text
PAUSED → COMPLETED
```

Prompt 9R must correct only this discrepancy.

---

# 1. REQUIRED FINAL BEHAVIOR

Normal Focus completion is allowed from:

```text
ACTIVE → COMPLETED
```

only.

A `PAUSED` session must NOT complete directly.

If the user wants to complete a paused session:

```text
PAUSED
→ resume
→ ACTIVE
→ complete
```

provided the completion criteria are satisfied.

Do not silently resume on behalf of the user.

---

# 2. PAUSED TIMER SEMANTICS

While status is:

```text
PAUSED
```

active study time must remain frozen.

Therefore:

```text
elapsedActiveSeconds
```

must NOT increase merely because wall-clock time passes.

And:

```text
completionEligible
```

for a normal paused session must be:

```text
false
```

even if wall-clock time has passed beyond `plannedEndAt`.

Remember that `plannedEndAt` is shifted on resume, so a correctly paused session should not naturally become eligible while paused anyway.

---

# 3. PAUSE REQUEST AT COMPLETION BOUNDARY

Prompt 9 already specifies the correct behavior.

If an `ACTIVE` session has already accumulated the planned Focus duration when the pause request arrives:

DO NOT persist:

```text
ACTIVE → PAUSED
```

Instead return:

```text
SESSION_READY_TO_COMPLETE
```

or the existing equivalent.

Keep the canonical Session:

```text
ACTIVE
```

so the legal transition remains:

```text
ACTIVE → COMPLETED
```

This behavior must now have explicit regression coverage.
