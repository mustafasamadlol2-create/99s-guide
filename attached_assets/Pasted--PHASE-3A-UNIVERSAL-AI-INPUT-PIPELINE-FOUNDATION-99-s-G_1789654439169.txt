# 5. PDF SUPPORT

PDF input is mandatory.

Support:

```text
application/pdf
```

Validation must include BOTH:

1. claimed MIME/type
2. actual binary signature

Do not trust extension or browser MIME alone.

At minimum verify a real PDF header such as:

```text
%PDF-
```

Use the project's existing PDF validation approach where appropriate, but extract reusable code rather than copying a large route implementation.

# 6. PDF SIZE LIMIT

The project already uses a 50 MiB limit for Lecture PDF uploads.

Gemini currently supports PDFs up to 50 MB.

For AI PDF inputs, establish a central configurable application limit that MUST NOT exceed the effective provider limit.

A reasonable default is:

```text
50 MiB maximum PDF input
```

Do not scatter `50 * 1024 * 1024` throughout the code.

Create a single configuration source.

If the repository distinguishes decimal MB and MiB, document the exact interpretation.

Reject oversized PDF input before any provider call.

# 12. PASTED TEXT SUPPORT

* preserve meaningful internal formatting
* preserve Arabic and English Unicode
* preserve question numbering
* preserve A/B/C/D formatting

# 15. FILENAME HANDLING

Uploaded filenames are untrusted metadata.

Never use raw user filenames directly for temporary filesystem paths.

Implement safe handling.

For temporary staged files use generated identifiers such as:

```text

```

or equivalent secure random identifiers.

Original filenames may be retained only as sanitized display metadata.

Prevent:

* `../`
* path traversal
* absolute paths
* reserved path manipulation
* control characters
* excessively long names

# 16. TEMPORARY FILE STAGING

PDF/image input may require a transient local file representation.

Create a dedicated abstraction, not scattered filesystem calls.

Possible conceptual name:

```text
AITemporaryFileManager
```

or equivalent.

Responsibilities:

* create safe temporary files
* use system/project temporary directory appropriately
* generate random filenames
* restrict lifecycle to the request/operation
* expose only necessary metadata
* delete files deterministically
* tolerate cleanup if file was already removed
* prevent path traversal
* never expose arbitrary filesystem reads

Do NOT use permanent application upload directories unless the existing architecture clearly requires them.

Prefer OS temporary storage or a dedicated transient AI directory.

---

# 17. CLEANUP MUST BE GUARANTEED

Temporary binary input must be cleaned using lifecycle-safe behavior.

Example principle:

```ts
const staged = await stage(...);

try {
  // future processing
} finally {
  await staged.cleanup();
}
```

Cleanup must execute on:

* success
* validation failure after staging
* provider failure
* timeout
* cancellation
* thrown exception

Avoid orphaned temporary files.
